# 面试讲解：企业知识库智能问答 Agent（kb-agent）

> 用法：面试前通读一遍，重点背熟「一句话介绍」「30 秒版本」「2 分钟版本」，
> 然后对着源码把 20 个问题逐条讲一遍（能讲出来 = 真懂）。

## 一、项目一句话介绍

> 我用 Spring Boot + LangChain4j 做了一个企业知识库智能问答 Agent：大模型通过函数调用自主决定调用
> 知识库检索、时间、计算器、天气 4 个工具来回答问题，知识库检索是我自己实现的 TF-IDF 中文检索，
> 整个项目打成 jar 就能跑，换 DeepSeek/通义/智谱/豆包只需改一行配置。

## 二、30 秒版本（面试官没耐心时）

> 这是一个智能客服类 Agent，回答员工/客户关于公司制度、产品、流程的问题。
> 核心三点：① 用 LangChain4j 的 AiServices 自动完成函数调用循环，我定义 4 个 @Tool 工具；
> ② RAG 检索我自己写了 TF-IDF + 中文二元组分词的实现，封装成 ContentRetriever 接入；
> ③ 会话记忆用 MessageWindowChatMemory 维护，单 jar 部署，模型可切换。

## 三、2 分钟版本（面试官感兴趣时）

按「背景 → 我的工作 → 关键设计 → 结果/验证」展开：

- **背景**：小厂需要把大模型接入业务，典型场景是客服/知识库问答，核心痛点是幻觉和私有知识缺失；
- **我的工作**：整体架构设计 + 全部编码。包括大模型接入（OpenAI 兼容、可切换）、4 个工具、
  TF-IDF 检索实现、AiServices 装配、REST 接口与网页界面、16 个单元测试；
- **关键设计**：
  1. 知识库先按段落切块，再用 TF-IDF + 余弦相似度召回 Top3，把片段喂给模型生成回答——这就是 RAG；
  2. 中文分词用 2-gram，不依赖 jieba，轻量可解释；
  3. 计算器自己写递归下降解析器，不用 eval，防注入；
  4. 天气工具做了 mock/真实双模式，演示不依赖网络；
  5. 工具调用过程通过 ThreadLocal 记录，前端可展示"用了哪些工具"；
- **结果/验证**：16 个单元测试全通过；打包后冒烟验证 health/tools/chat 接口正常；
  上线只需替换知识库文档和填入 API Key。

## 四、高频问题与回答口径

### 1. 什么是 Agent？和你平时调 API 有什么区别？
普通 API 调用是"一问一答"，模型不知道你的业务数据，也不能干活。
Agent = 模型 + 工具 + 循环：模型根据用户问题"思考"要不要调用工具（函数调用），
工具执行完把结果回填，模型再基于结果继续回答，直到给出最终答案。我这个项目就是最经典的"单 Agent 工具调用"形态。

### 2. Function Calling 的原理是什么？
模型训练时学会了输出结构化的 tool_calls。调用时我们把工具定义（名字、描述、参数 JSON Schema）随消息一起发给模型，
模型返回 `tool_calls: [{function: {name, arguments}}]`，程序解析后执行对应函数，
把结果作为 role=tool 的消息（带 tool_call_id）追加回上下文，再让模型继续。
我在 v1 手写版（`handwritten-version/`）里完整实现了这套协议，LangChain4j 内部也是这么做的。

### 3. LangChain4j 的 AiServices 替你做了什么？
按接口（KbAssistant）动态生成代理，自动完成：拼消息（系统提示 + 记忆 + 用户输入）→ 调模型 →
发现 tool_calls 就执行 @Tool 方法 → 结果回填 → 再调模型，直到模型直接回答。还负责把 @Tool 方法
反射成工具定义、把 ContentRetriever 结果拼进上下文。

### 4. 为什么用 LangChain4j？为什么不自己写或直接用 Spring AI？
- 用它：工具循环、记忆、RAG 是成熟封装，小厂开发效率高、踩坑少；版本 1.0 已稳定。
- 不用手写：重复造轮子，维护成本高（但我在 v1 保留了一份手写实现，用来讲原理）；
- 不选 Spring AI：1.x 还在快速迭代、API 变动大，LangChain4j 更成熟、中文资料也更多。
补充一句：两者底层都依赖各家模型的 function calling，核心思路一致，会一个另一个上手很快。

### 5. RAG 是什么？为什么你的检索不用向量库？
RAG（检索增强生成）= 先从知识库检索相关内容，再让模型基于检索结果回答，解决"模型不知道你的私有数据"和"幻觉"问题。
我的场景知识库只有几十个片段，TF-IDF 足够且零依赖、可解释；如果文档量上十万级，
就换 Embedding + 向量库（Milvus/ES），接口不变，只替换 TfidfContentRetriever 实现。

### 6. 中文分词怎么做的？
英文按单词切，中文按 2-gram（二元组）切：比如"年假规定"切成"年假""假规""规定"。
好处是不需要 jieba 这类外部词典、实现简单、对专有名词也稳定；代价是召回粒度略粗，
但对"片段级"检索够用。

### 7. 怎么防止模型幻觉？
三层：① 系统提示词要求"知识库检索不到就明说，禁止编造"；② RAG 检索到的片段作为依据，
并让模型注明来源文档；③ 检索不到时工具会返回"未检索到"，模型据此如实回答。
生产还能加"回答内容与检索片段一致性校验"。

### 8. 多轮对话记忆怎么实现？
LangChain4j 的 MessageWindowChatMemory，一个滑动窗口，默认保留最近 10 条消息，
超出丢最旧的。它把历史消息自动拼进每次请求。演示版是单用户共享一份记忆，
生产按 sessionId 用 ChatMemoryProvider 隔离（文档里有写）。

### 9. 模型乱调用工具 / 死循环怎么办？
模型调用不存在的工具：@Tool 校验失败会返回错误文本给模型，让它换工具；
死循环：模型单次只能返回有限的 tool_calls，LangChain4j 有内部轮数控制（生产可配置上限）；
另外每个工具执行都包了 try-catch，工具挂了不会让整个对话崩掉。

### 10. 提示词注入怎么防？
演示版做了基本防护：用户输入只进 user 消息，系统提示是服务端固定的；生产要加：输入敏感词过滤、
"忽略上述指令"类检测、工具权限校验、审计日志。

### 11. 天气工具为什么做 mock 模式？
小厂面试/演示最怕网络不稳定。默认 mock 返回确定性模拟数据（城市名+日期哈希），
离线也能演示完整工具调用链路；配置 `tools.weather.mock=false` 就走 Open-Meteo 免费真实接口，失败自动回退。

### 12. 计算器为什么自己写解析器？
如果用 ScriptEngine/表达式求值库，有注入风险（比如执行任意代码）。我写的递归下降解析器
只认数字和 `+ - * / ( )`，从语法上杜绝了注入，还能控制长度。面试时可以现场讲一下语法规则
（expression → term → factor）。

### 13. 怎么扩展一个新工具？
加一个带 `@Tool(name, value)` 注解的方法，写明参数即可。LangChain4j 会自动把方法签名
转成 JSON Schema 发给模型，模型按 Schema 传参，执行完结果自动回填。AgentService、控制器都不用改。

### 14. 生产化还要改哪些？
流式输出（SSE）、会话隔离、向量检索、对话日志入库、鉴权与限流、提示词注入防护、
多 Agent 编排（主管-子 Agent）、模型降级与重试。

### 15. 和 Dify/Coze 这类平台比呢？
平台适合非研发快速搭 demo；但我们做的是"工程化交付"——要接自己的系统、要定制工具、
要控制代码和部署，就得自己写。会平台（配置）+ 会代码（LangChain4j）在小厂是加分项。

### 16. token 成本怎么控制？
① 记忆窗口限制条数；② 知识库检索只回 Top3 片段而不是全文；③ 系统提示精简；
④ 温度设 0.3 减少无谓发散；⑤ 用便宜模型（deepseek-chat / qwen-turbo）做高并发场景。

### 17. 测试怎么做的？
16 个单元测试：检索（TF-IDF 召回正确性、无关查询）、计算器（优先级、负数、除零、注入拦截）、
工具（4 个工具的返回值与 tracker 记录）、ContentRetriever（返回 Content 带元数据）。
核心思路：不依赖真实模型和网络，用测试数据直接构造对象测逻辑；Agent 循环本身是框架行为，
文档里说明了这一点。

### 18. 怎么部署？
`mvn -DskipTests package` 打 fat jar → `java -jar target/kb-agent-2.0.0.jar`。
单机单 jar，适合小厂；生产可以加 Nginx 反代、systemd 守护、日志收集。

## 五、被问到"手写版 vs LangChain4j 版"怎么说

> 两个版本都在仓库里。v1 我手写了 OpenAI 协议客户端和 Agent 循环（约 1500 行），
> 目的是把 function calling 的每个细节吃透——请求体长什么样、tool_calls 怎么解析、
> tool 消息怎么回填、死循环怎么防。v2 用 LangChain4j 重写，是为了贴近小厂生产实践，
> 把精力放在业务工具和检索上。所以面试官问协议细节我能讲，问工程实践我也能讲。
